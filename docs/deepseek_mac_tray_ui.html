Technical & UI Implementation Architecture

1. Main Overview Dashboard & Y-Axis Scaling

  • Dynamic Y-axis formatted in K tokens (`500k`, `250k`, `0k`) calculating dynamic upper bounds.
  • Includes header minimize button (`↘↖`) to collapse into Option 4 Mini Interface.
  • 7-day or 30-day rolling total breakdown (via Extended View Style) with per-API key allocation percentages, top notch ticks, 90° rotated vertical dates (`shortDateLabel`), and hover dashed guidelines.

2. Dual Auth Architecture (Simultaneous UI)

  • Presents Portal Email & Password and Google SSO simultaneously.
  • Portal Auth Mode: Direct platform credential authentication saved to macOS Hardware Keychain (`googleToken`).
  • Google SSO Mode: Spawns WKWebView modal targeting platform.deepseek.com for session header capture.

3. Preferences & Tray Options

  • Configurable polling intervals, Extended View Style (7 Days / 30 Days), launch at login options, and startup default mode.
  • Supports dynamic menu bar string formatting (`DS: 42.8k/h` or `DS: 1.48M`).

4. Option 4: Compact Mini Interface

  • Compact 1/4th footprint designed for rapid glanceability.
  • Renders the 7-day trend (daily granularity) with dynamic Y-axis in K tokens (`231M`, `115M`, `0`); the platform API no longer exposes hourly buckets, so the widget shows `Avg: X/day`.
  • Includes 3-hour X-axis time marks (`8 AM`, `11 AM`, `2 PM`, `5 PM`) and an Expand Dashboard button (`↖↘`) to restore View 1.

5. Tray Context Menu (Right-Click)

  • Left-click toggles the popover (Main Overview / Mini / Preferences / Auth).
  • Right-click pops the context menu: Refresh Now (`⌘R`), Open Dashboard, Open Mini Widget, Preferences… (`⌘,`), separator, Quit DeepSeek Tray (`⌘Q`).
  • Menu items route through the same UsageTracker state as the popover views.
  • Note: dashboard usage totals populate automatically — the SSO sheet's JS interceptor captures the platform's usage API (endpoint + headers) and replays it via DiscoveredDashboardUsageClient: requests/tokens/daily/key-breakdown from /api/v0/usage/by_api_key/amount (data.biz_data.series[].buckets[]), monthly spend + currency from the billing API /api/v0/usage/cost?month=&year=.

6. SSO Discovery Flow

  • "Sign in with Google" opens a standalone WKWebView window (never a sheet on the tray popover — a transient popover closes on resign-key and would hide the sheet).
  • The sheet presents as Safari (custom user agent) and injects a fetch/XHR interceptor at .documentStart (all frames), forwarding url / method / status / body (≤30KB) / headers.
  • Auth is header-based, not cookie-based: the platform SPA sends a Bearer JWT per-request (authorization + x-client-*); no session cookie ever exists.
  • On the first usage-shaped response, the sheet stores ds_discovered_usage_endpoint (url, method, headers — no bodies) and auto-closes; endpoint persists across launches.
  • DiscoveredDashboardUsageClient replays it: relative URLs resolved against https://platform.deepseek.com, captured headers as auth (Keychain cookie attached only if present).
